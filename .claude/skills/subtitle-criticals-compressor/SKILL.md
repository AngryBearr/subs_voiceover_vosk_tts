# Subtitle criticals compressor

Этот скилл помогает обрабатывать JSON субтитров, в котором уже есть тайминговый анализ
(`analysis`), и нужно сократить только критичные по длительности реплики, сохранив смысл.

## Формат входного JSON

Ожидается список объектов вида:

```jsonc
[
  {
    "text": ["строка 1", "строка 2"],
    "index": 1,
    "start": 3800,
    "end": 6080,
    "analysis": {
      "duration_sec": 2.28,
      "estimated_sec": 3.92,
      "mismatch_ratio": 1.72,
      "diff_sec": 1.64,
      "extended_duration_sec": 2.9,
      "extended_mismatch_ratio": 1.35,
      "used_gap_sec": 0.62,
      "words_count": 6,
      "is_short_segment": false,
      "is_checked": true,
      "is_critical": true
    }
  }
]
```

Поле `text` может быть строкой или списком строк, но при обновлении мы приводим его
к списку из одной строки (по конвенциям проекта).

## Общий алгоритм работы

1. Загрузить входной JSON (список объектов-сегментов).
2. Построить **глобальный контекст**: склеить все `text` всех сегментов в один длинный
   текст, разделяя сегменты переводами строк. Использовать этот текст как общий контекст
   для всех запросов к агенту.
3. Пройти по каждому сегменту по порядку; если `analysis.is_critical == true`, то:
   - Получить его локальный текст (склейка `text` в одну строку).
   - Сформулировать запрос к агенту: дать глобальный контекст + проблемный сегмент и
     попросить **сильно сократить** текст, сохранив смысл и естественную речь, при этом:
     - не менять факты;
     - не ломать структуру и интонацию, если это критично для сцены;
     - оставлять текст на русском.
   - Получить от агента **одну строку** с новым, сокращённым текстом.
4. После того как все критичные сегменты обработаны агентом и есть словарь
   `index -> new_text`, вызвать Python‑функцию
   `process_json_items(items, compressed_texts, avg_chars_per_sec, max_mismatch_ratio)`
   из `scripts/process_critical_segments.py`:
   - она подставит новые тексты в нужные сегменты (`text = [new_text]`),
   - пересчитает для них поле `analysis` с помощью существующей логики
     `utils.analyze_text.analyze_subtitles`.
5. Вернуть обновлённый список объектов‑сегментов как JSON.

## Детали реализации (для агента)

### Сбор контекста

Используй вспомогательную функцию `build_context(items)` из
`scripts/process_critical_segments.py` или повтори её логику напрямую:

- для каждого элемента взять поле `text`;
- если это список, склеить в одну строку через пробел;
- добавить в список контекста, отбросив пустые строки;
- финальный контекст — это строки, соединённые через `"\n"`.

### Обработка одного критичного сегмента

Для каждого сегмента `item` с `analysis.is_critical == true`:

1. Локальный текст: используй `join_text_lines(item.get("text", ""))`
   из `utils.analyze_text`.
2. Сформируй промпт примерно такого вида (вольная формулировка допускается):

   > У тебя есть общий контекст субтитров (вступление, соседние реплики и т.п.) и
   > конкретный проблемный сегмент, который не помещается в свой тайм‑слот.
   > Нужно сократить текст сегмента, максимально сохранив его смысл и интонацию,
   > но сделав фразу заметно короче. Не добавляй новых фактов, не искажайте существующие.
   > Верни только одну финальную фразу без пояснений.

3. Передай агенту:
   - `context` — глобальный текст,
   - `segment_text` — текущий локальный текст,
   - метаданные можно добавить (index, длительность, желаемое сокращение), но не обязательно.
4. Результат интерпретируй как **новый текст сегмента**.

### Пересчёт analysis после сжатия

Модуль `utils.analyze_text` уже умеет считать все метрики. Чтобы не дублировать
логику, скрипт `scripts/process_critical_segments.py` предоставляет функцию

- `recompute_analysis_for_item(item, avg_chars_per_sec, max_mismatch_ratio)` —
  пересчитывает поле `analysis` для одного элемента;
- `process_json_items(items, compressed_texts, avg_chars_per_sec, max_mismatch_ratio)` —
  применяет новые тексты ко всем критичным сегментам и пересчитывает `analysis`.

При обычном использовании внутри скилла достаточно вызывать только
`process_json_items` после того, как собран `compressed_texts`.

Параметры `avg_chars_per_sec` и `max_mismatch_ratio` по умолчанию берутся из
`utils.analyze_text` (`DEFAULT_AVG_CHARS_PER_SEC` и `DEFAULT_MAX_MISMATCH_RATIO`).
Меняй их только если пользователь явно просит другой порог.

## Типичный сценарий вызова скилла (две фазы)

### Фаза 1: агент сокращает все критичные реплики

1. Пользователь даёт JSON с уже посчитанным `analysis`.
2. Загрузить JSON в список `items`.
3. Построить `context = build_context(items)`.
4. Создать пустой словарь `compressed_texts: dict[int, str] = {}`.
5. Для каждого `item` в `items`:
  - если `item["analysis"]["is_critical"]` не true — пропустить;
  - иначе вызвать агента для сжатия текста (используя `context` + локальный текст
    сегмента), сохранить результат в `compressed_texts[item["index"]]`.
6. По завершении этой фазы можно (опционально) сохранить карту сокращённых текстов
  в отдельный файл JSON, например `temp/subs_compressed_map.json`:

  ```jsonc
  {
    "1": "Из этой малазийской деревушки...",
    "6": "Мы берём две!"
  }
  ```

### Фаза 2: применение сокращений и пересчёт analysis

1. Вызвать Python‑код:

  ```python
  from .scripts.process_critical_segments import process_json_items

  updated_items = process_json_items(items, compressed_texts)
  ```

  или использовать готовый CLI:

  ```bash
  uv run -m .claude.skills.subtitle-criticals-compressor.scripts.apply_compressed_texts \
    path/to/input_analyzed.json \
    path/to/subs_compressed_map.json \
    -o path/to/output_analyzed_compressed.json
  ```

2. На выходе получается обновлённый JSON с:
  - обновлёнными текстами (`text` сокращён для критичных сегментов);
  - заново пересчитанным `analysis` для этих сегментов;
  - сохранённой структурой остальных полей.

## Что важно сохранить

- Не менять структуру JSON (поля `index`, `start`, `end` и т.д.).
- Поле `text` на выходе — **список строк**, даже если строка одна.
- Длина массива `items` должна сохраняться.
- Поле `analysis` должно быть перезаписано только через логику
  `utils.analyze_text`, а не вручную.
