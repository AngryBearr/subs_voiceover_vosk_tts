# Separate overlapping voices without overstating evidence

**The Telegram comparisons favor diarizers, not a proven new blind three-voice
separator.** DiariZen is a useful conditional overlap-detector candidate, while
PixIT already offers three source slots but failed automatic third-voice detection
in our saved fixture. OpenRouter MAI provides a synchronous final response, not a
documented whole-audio async job or processing percentage. The full Australian
Survivor episode is already complete; no paid repeat is needed. GPU setup still
requires administrative loading of the installed NVIDIA module, and **no CPU/GPU
speedup has been measured**. This report synthesizes supplied October 12, 2026 primary
research and preserved local evidence; no new network, model or privileged action
was performed ([model notes](../research_notes/Диаризация%20и%20разделение%20голосов/model_primary_verification.md),
[MAI notes](../research_notes/Диаризация%20и%20разделение%20голосов/mai_whole_file.md)).

## MAI offers synchronous waiting, not a documented job percentage

OpenRouter STT documents final JSON, a **60s upstream processing deadline** and a
**25MB MAI/Azure upload limit**. MP3 is supported by its guide; our WAV-only client
is a narrower safety choice. Compression reduces bytes, not processing timeout:
the approximately **107.6MB** episode PCM is oversized, but no universal impossibility
claim for compressed whole-file input follows ([STT guide](https://openrouter.ai/docs/guides/overview/multimodal/stt),
[endpoint](https://openrouter.ai/docs/api/api-reference/stt/create-transcription)).
OpenRouter batches exclude audio transcriptions; `X-Generation-Id` is cost/debug
tracking, not a transcription job, and `session_id` does not bind provider speaker
identity ([batches](https://openrouter.ai/docs/batch-quickstart)).

Direct Azure MAI uses synchronous multipart `transcriptions:transcribe`, API version
**2025-10-15**, with `enhancedMode` MAI selection and separate Azure credentials.
The versioned **<2h/<250MB** limits arithmetically fit this episode, but MAI diarization
supports unspecified shorter audio and preview has no SLA; larger generic quotas
are not MAI guarantees ([MAI](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-transcribe),
[REST](https://learn.microsoft.com/en-us/rest/api/speechtotext/transcriptions/transcribe?view=rest-speechtotext-2025-10-15)).
Generic Azure batch statuses do not establish MAI batch compatibility
([batch status](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/batch-transcription-get)).

One sync call can expose **uploading/waiting/elapsed/done**, not invented server percent.
Our completed run already logged each unique completed chunk: **57 requests, 660 cues,
$0.09344444444444445 episode cost; $0.1011395548888889 / 72 shared reservations**, all
costs known ([summary](../temp/australian_survivor_e04_mai/summary.json)). Speaker IDs
remain request-scoped. Native timestamps/labels do not produce clean stems; cutting
a mixed waveform retains overlap. No additional progress UI or upload was implemented.

## Conclusion

Prioritize three bounded studies: **DiariZen→existing SepFormer** overlap triggering
only after accepting appropriate noncommercial terms; **existing PixIT versus
SepFormer** on identical true-three-speaker spans; optionally **SAM Audio assisted
extraction**, with target leakage checked and no blind-separation claim. MossFormer2
is a two-voice control, not a demonstrated third-voice remedy. New acceptance must
show independent source coverage and identity binding: a diarization-table winner
alone cannot resolve the project's missed-overlap trigger.
