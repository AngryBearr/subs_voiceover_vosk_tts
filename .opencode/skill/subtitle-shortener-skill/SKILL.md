# Subtitle Shortener Skill

## Когда использовать

- JSON-сабы с полем `analysis` (см. `assets/subs_analyzed.json`)
- Нужно сократить реплики с `mismatch_ratio >= 1.5` ИЛИ `extended_mismatch_ratio >= 1.5`
- **Нет ограничения** на процент сокращения — сокращай текст сколько нужно
- Цель: достичь `mismatch_ratio <= 1.5` после пересчёта

---

## ⚠️⚠️⚠️ КРИТИЧЕСКИ ВАЖНО: Полная обработка всех субтитров

**ТЫ — агент, который выполняет сокращение.** Не поручай это внешней модели (за исключением использования суб-агентов, см. ниже).
Ты читаешь payload, сокращаешь тексты сам (или через суб-агентов), применяешь результаты.

### Делегирование и ускорение (Суб-агенты)

Если у тебя доступен инструмент для вызова суб-агентов (например, `runSubagent`), ты можешь (и это рекомендуется для больших объёмов) делегировать задачи по сокращению частей субтитров суб-агентам.
- Раздели общий список субтитров на логические батчи (см. "Батчинг").
- Запусти суб-агентов для параллельной обработки этих батчей.
- Собери ответы и примени их последовательно.

### Батчинг (Разделение на части)

Для работы с большими файлами или при использовании суб-агентов используй флаги `--limit` и `--offset` в режиме `payload`. Ты можешь запрашивать любое количество сегментов (например, по 10, 30 или 50 штук), которое считаешь оптимальным.

```powershell
# Запросить первые 30 сегментов, требующих сокращения
uv run python .opencode/skill/subtitle-shortener-skill/scripts/subtitle_shortener_skill.py input.json --mode payload --limit 30

# Запросить следующие 30 (offset = количеству уже запрошенных)
uv run python .opencode/skill/subtitle-shortener-skill/scripts/subtitle_shortener_skill.py input.json --mode payload --limit 30 --offset 30
```

### Обязательное условие завершения задачи

**Задача считается ВЫПОЛНЕННОЙ только когда ВСЕ субтитры с `mismatch_ratio >= 1.5`
были сокращены и пересчитаны.**

Если количество субтитров для сокращения большое и ты решаешь разбить обработку на батчи:

1. **НЕ ОСТАНАВЛИВАЙСЯ** после первой части
2. После применения и пересчёта первой порции — продолжай со следующей
3. Повторяй, пока ВСЕ сегменты не будут обработаны
4. **Проверяй результат** через `get_segments_needing_further_shortening()`
5. Если остались сегменты с ratio > 1.5 — сокращай их повторно
6. **Очистка:** После получения финального результата удали все временные файлы (`payload.json`, `response.json` и др.), которые ты создавал.

**Недопустимо:** сократить часть субтитров и сказать «готово» или «продолжить?».
Ты должен автоматически продолжать обработку до полного завершения.

## Константы

```python
TARGET_MISMATCH_RATIO = 1.5      # Целевой максимальный ratio после сокращения
MIN_MISMATCH_RATIO_FOR_SHORTENING = 1.5  # Порог для отбора сегментов
MAX_COMPRESSION_ATTEMPTS = 5     # Лимит попыток
```

**ВАЖНО:** Ограничение MAX_SHORTENING_PERCENT = 30% **УДАЛЕНО**. 
Модель теперь может сокращать текст на любой процент, главное — 
достичь `ratio <= 1.5` после пересчёта.

## Пайплайн

1. `load_items(path)` — загрузка JSON
2. `collect_segments_for_agent(items)` — сбор сегментов с `ratio >= 1.5`
3. `build_agent_payload(items)` — формирование payload
4. **Ты (агент) сокращаешь тексты** и формируешь ответ `{"index": "сокращённый текст", ...}`
5. `parse_agent_response(raw)` — парсинг твоего ответа
6. `apply_all_compressions(items, compressed)` — применение всех сокращений
7. `recompute_full_analysis(items)` — пересчёт таймингов
8. `get_segments_needing_further_shortening(items)` — проверка, нужны ли ещё итерации
9. Если есть сегменты с ratio > 1.5 — **повторяй сокращение** для них
10. **Продолжай до тех пор, пока ВСЕ сегменты не достигнут ratio <= 1.5**
11. `save_items(path, items)` — сохранение
12. `format_shortened_subtitles(items)` — вывод результата в формате `{index: text}`

## Основные функции

| Функция | Назначение |
|---------|------------|
| `collect_segments_for_agent(items)` | Сбор сегментов с `ratio >= 1.5` (без проверки `is_critical`) |
| `build_agent_payload(items)` | JSON-payload для сокращения |
| `parse_agent_response(raw)` | `dict[int, str]` из ответа агента |
| `apply_all_compressions(items, compressed)` | Применяет все сокращения (без ограничений) |
| `get_segments_needing_further_shortening(items)` | Находит сегменты с `ratio > 1.5` после сокращения |
| `build_retry_prompt_context(items, segments)` | Контекст для повтора |
| `format_shortened_subtitles(items)` | `{index: text}` для сокращённых |
| `print_shortened_subtitles(items)` | Печать сокращённых в JSON |
| `recompute_full_analysis(items)` | Пересчёт `analysis` для всех |

## Формат твоего ответа

Когда ты сокращаешь субтитры, результат должен быть в формате:

```json
{"1": "Сокращённый текст...", "8": "Другой текст..."}
```

Ключи — индексы сегментов (строки), значения — сокращённые тексты.

## Формат вывода сокращённых субтитров

После обработки можно вывести сокращённые субтитры:

```json
{
  "1": "Из этой малазийской деревушки...",
  "8": "Вы видите начало приключения!",
  "9": "Им дали две минуты захватить всё с лодки!"
}
```

## Пример: итеративное сжатие

```python
from scripts.subtitle_shortener_skill import (
    load_items, save_items, build_agent_payload, parse_agent_response,
    apply_all_compressions, recompute_full_analysis,
    get_segments_needing_further_shortening, build_retry_prompt_context,
    format_shortened_subtitles, MAX_COMPRESSION_ATTEMPTS,
)

items = load_items("input.json")

for attempt in range(1, MAX_COMPRESSION_ATTEMPTS + 1):
    payload = build_agent_payload(items)
    # Ты (агент) анализируешь payload и генерируешь сокращённые тексты
    # raw_response = твой ответ в формате {"index": "сокращённый текст", ...}
    compressed = parse_agent_response(raw_response)
    items = apply_all_compressions(items, compressed)
    items = recompute_full_analysis(items)
    
    # Проверяем, нужны ли ещё итерации
    still_need = get_segments_needing_further_shortening(items)
    if not still_need:
        break  # ВСЕ сегменты достигли ratio <= 1.5
    
    retry_context = build_retry_prompt_context(items, still_need)
    # Продолжай сокращать оставшиеся сегменты!

save_items("output.json", items)

# Вывод сокращённых субтитров
shortened = format_shortened_subtitles(items)
print(shortened)  # {"1": "...", "8": "...", ...}
```

### ⚠️ ВАЖНО: Обработка по частям

Если сегментов много и ты решаешь обработать их частями:

1. Обработай первую порцию (например, сегменты 1-50)
2. Примени результат, пересчитай analysis
3. **Сразу переходи к следующей порции (51-100)**
4. Повторяй до тех пор, пока ВСЕ сегменты не будут обработаны
5. После обработки всех — проверь `get_segments_needing_further_shortening()`
6. Если есть с ratio > 1.5 — запусти повторное сокращение для них

**Задача НЕ выполнена**, пока все сегменты не достигнут ratio <= 1.5!

## Правила сжатия (для тебя, агента)

- Сжимать только сегменты из `segments`
- Использовать `context` для связности, не трогать соседние реплики
- **Нет ограничения на процент сокращения** — сокращай сколько нужно
- Цель: достичь `mismatch_ratio <= 1.5` после пересчёта
- Нельзя: менять смысл, добавлять факты, переводить
- **Обработать ВСЕ сегменты** — не останавливаться на части

## 🚫 СТРОГО ЗАПРЕЩЕНО

### Запрещённые методы сокращения

1. **НЕ создавать скрипты для сокращения** — никаких Python/bash скриптов,
   которые пытаются автоматически обрезать или модифицировать текст
2. **НЕ использовать обрезку с многоточием** — недопустимо:
   - `"Это очень длинная строка"` → `"Это очень длинная..."`
   - `"Привет, как дела?"` → `"Привет..."`
3. **НЕ применять механическое удаление слов** — нельзя просто убирать
   слова без понимания контекста и смысла
4. **НЕ использовать регулярные выражения** для сокращения текста
5. **НЕ заменять фразы на сокращения** типа `"и так далее"` → `"и т.д."`

### Единственный допустимый метод

**Ты (агент/LLM) выполняешь сокращение:**
- Переформулируй текст короче, **сохраняя полный смысл**
- Сокращённый текст должен быть законченным предложением
- Нельзя терять важную информацию из оригинала
- Перефразирование должно звучать естественно на русском языке
- **Обработай ВСЕ сегменты с ratio >= 1.5 до конца**

### Примеры правильного и неправильного сокращения

| Оригинал | ❌ НЕПРАВИЛЬНО | ✅ ПРАВИЛЬНО |
|----------|----------------|--------------|
| "Им дали две минуты на то, чтобы захватить с собой всё, что они смогут" | "Им дали две минуты..." | "У них две минуты, чтобы взять всё возможное" |
| "Этот человек покинет этот остров с миллионом долларов" | "Этот человек покинет..." | "Победитель получит миллион долларов" |
| "Мы хотим хотя бы ближе подобраться к острову" | "Мы хотим ближе..." | "Хотим приблизиться к острову" |

## Проверка результатов

После каждой порции сокращений **обязательно**:

1. Пересчитать `analysis` через `recompute_full_analysis(items)`
2. Проверить `get_segments_needing_further_shortening(items)`
3. Если есть сегменты с `ratio > 1.5` — **сразу повторить сокращение**
4. **НЕ ОСТАНАВЛИВАТЬСЯ** до тех пор, пока все сегменты не достигнут ratio <= 1.5

### Цикл проверки

```
┌─────────────────────────────────────────────────────────┐
│  1. Получить сжатые тексты от модели                    │
│  2. Применить все сокращения (apply_all_compressions)   │
│  3. Пересчитать analysis (recompute_full_analysis)      │
│  4. Проверить ratio каждого сокращённого сегмента       │
│  5. Если есть с ratio > 1.5:                            │
│     → Сформировать retry-контекст                       │
│     → Выполнить дополнительное сокращение               │
│     → Вернуться к шагу 2                                │
│  6. Повторять, пока ВСЕ сегменты не достигнут ratio<=1.5│
│  7. Сохранить результат                                 │
│  8. Вывести сокращённые субтитры в формате {idx: text}  │
└─────────────────────────────────────────────────────────┘
```

Максимум попыток на один сегмент: `MAX_COMPRESSION_ATTEMPTS = 5`

## ✅ Условия завершения задачи

Задача считается **ВЫПОЛНЕННОЙ** только когда:

1. ✅ ВСЕ сегменты с изначальным `mismatch_ratio >= 1.5` были обработаны
2. ✅ После пересчёта `recompute_full_analysis()` НЕТ сегментов с ratio > 1.5
3. ✅ Результат сохранён в выходной файл
4. ✅ Выведен итоговый отчёт `format_shortened_subtitles(items)`

**НЕ СЧИТАЕТСЯ ВЫПОЛНЕННЫМ:**
- ❌ Обработана только часть сегментов и агент «ждёт продолжения»
- ❌ Есть сегменты с ratio > 1.5 после обработки
- ❌ Агент предлагает «продолжить?» вместо автоматического продолжения

## Структура payload сегмента

```json
{
  "context": "текст 3 соседей до и после",
  "index": 1,
  "text": "Исходный текст...",
  "duration_sec": 2.28,
  "estimated_sec": 3.92,
  "mismatch_ratio": 1.72,
  "extended_mismatch_ratio": 1.35
}
```

**Важно:** 
- Сегмент попадает в payload если `mismatch_ratio >= 1.5` ИЛИ `extended_mismatch_ratio >= 1.5`
- Флаг `is_critical` **НЕ используется** для отбора
- Поле `extended_mismatch_ratio` может быть `null`
