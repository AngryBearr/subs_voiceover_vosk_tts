# Русская озвучка английского видео

[English](../README.md) | **Русский**

Репозиторий превращает английскую серию (делался и проверялся на реалити-шоу вроде Survivor и
The Amazing Race) в видео с русской закадровой озвучкой. Вы даёте видеофайл или целый сезон, на
выходе получаете по одному `.mkv` на серию, в котором есть:

- несколько русских звуковых дорожек (одна и та же озвучка, сделанная разными голосовыми
  движками, их до трёх),
- оригинальный звук,
- русские субтитры.

Русские голоса накладываются на оригинальный звук, который приглушается, пока звучит русская
реплика. По возможности каждый человек говорит своим (клонированным) голосом, а если это
невозможно, то хотя бы подходящим мужским или женским.

Всё работает из командной строки или со страницы в браузере на вашем компьютере.

## 1. Что остаётся на компьютере, а что уходит в сеть

| Шаг | Где выполняется | Что уходит с компьютера |
|---|---|---|
| Декодирование звука, распознавание речи, кто и когда говорит, пол, текст на экране, синтез голоса, проверка речи, сведение, кодирование видео | ваша видеокарта и процессор | ничего |
| Объединение двух расшифровок, словарь сезона, имена говорящих, перевод, сокращение длинных реплик, проверка ударений | языковая модель (ИИ-сервис, работающий с текстом) | только текст: английские реплики, имена, русские реплики |
| Состав сезона | статья в Википедии, которую программа находит сама, либо языковая модель с поиском в интернете | название шоу и сезона, взятое из имён папки и файлов |
| Готовые субтитры (необязательно, по умолчанию включено) | ищутся в видеофайле, рядом с ним, в локальном архиве, затем в интернете | идентификатор шоу, номер сезона и серии; файл субтитров скачивается |
| Скачивание моделей | Hugging Face, только при первом запуске | ничего из ваших файлов |

Звук и видео с компьютера не уходят. Поиск субтитров в интернете можно отключить
(`--no-subtitles` или набор `fast`).

К языковым моделям по умолчанию обращаются через OpenRouter. Вместо этого можно использовать
подписку ChatGPT через программу OpenCode или сервис OrcaRouter; см.
[раздел 4](#4-ключи-и-личные-настройки) и «Language models» в `docs/stt_local.md`.

## 2. Требования

- Linux. Скрипты проверяют это и останавливаются на другой системе.
- Видеокарта NVIDIA и драйвер с поддержкой CUDA 12.8 или новее. `scripts/install.sh` предупредит,
  если видеопамяти меньше 12 ГБ. У автора RTX 4070 Ti SUPER на 16 ГБ; на других картах ничего
  не измерялось.
- Диск: установщик предупреждает, если свободно меньше 40 ГБ в папке проекта или в кэше моделей
  (`~/.cache/huggingface` или `$HF_HOME`). Примерно: окружения Python 15 ГБ, скачанные модели
  около 30 ГБ при первой установке, рабочие файлы около 2 ГБ на серию.
- `git`, `curl` и `uv` (быстрый установщик пакетов Python; установщик предложит поставить его
  сам). Системный `ffmpeg` не нужен.
- Учётные записи и ключи:
  - бесплатная учётная запись Hugging Face и токен на чтение; кроме того, на страницах двух
    моделей нужно согласиться с условиями (`pyannote/speaker-diarization-community-1` и
    `CohereLabs/cohere-transcribe-03-2026`);
  - ключ OpenRouter (платный, оплата за запросы) для шагов с языковой моделью, если вы не
    используете другой путь (раздел 4).
- У части моделей некоммерческие лицензии (например, веса DiariZen — CC BY-NC 4.0; модель
  возраста и пола — CC-BY-NC-SA-4.0). Перед коммерческим использованием проверьте их. Файла
  лицензии в самом репозитории пока нет.

## 3. Установка

```bash
bash scripts/install.sh            # всё: ещё и ESpeech (голоса самих героев) и DiariZen
bash scripts/install.sh --basic    # только голоса Vosk и TeraTTS, говорящих ищет pyannote
subs_env/bin/python -m stt.selftest          # проверка: видеокарта, пакеты, модели, ключи
subs_env/bin/python -m stt.selftest --quick  # то же без скачивания
```

Установщик проходит шесть шагов: проверяет компьютер, создаёт окружения Python, скачивает модель
голосов Vosk, помогает войти в Hugging Face, спрашивает ключ OpenRouter (он записывается в
`.env` и никогда не показывается), запускает самопроверку (именно тут скачиваются те ~30 ГБ
моделей) и может добавить ярлык в меню. После `git pull` запустите его ещё раз: уже сделанные
шаги пройдут быстро. Окружения можно создавать и по одному:
`bash scripts/setup_envs.sh [main|f5|diarizen|qwen]`.

Окружения Python:

| Папка | Зачем |
|---|---|
| `subs_env` | почти всё: распознавание, перевод, Vosk и TeraTTS, проверка речи, сведение, интерфейс |
| `f5_env` | ESpeech (F5-TTS), голоса, клонированные с героев. Сначала нужен `subs_env` |
| `diarizen_env` | DiariZen v2, модель «кто и когда говорит» по умолчанию. Без неё берётся pyannote |
| `stt_qwen_env` | необязательное, только для сравнений с Qwen3-ASR; пайплайн его не использует |

Все команды ниже запускаются из корня репозитория. `uv run -m ...` и
`subs_env/bin/python -m ...` равнозначны.

**Обученных весов модели голосов в git нет.** Файла `models/speaker/resnet293-ft/avg_model.pt`
(115 МБ) в репозитории нет, он лежит на
[Hugging Face](https://huggingface.co/AngryBear9019/wespeaker-resnet293-survivor-ft). Галочка на вкладке «Обработка»
скачивает его один раз перед началом работы (в командной строке: `stt.run --download-voice-model`). Без него пайплайн пишет предупреждение в лог и берёт обычную модель
`resnet293`, она чуть менее точна (раздел 10). Как веса получены — в
[разделе 19](#19-обучение-модели-голосов).

## 4. Ключи и личные настройки

Ключи кладутся в `.env` в корне репозитория (он в `.gitignore`). Имена, которые ищет код:

- `OPENROUTER_API_KEY` — языковые модели через OpenRouter (путь по умолчанию);
- `ORCAROUTER_API_KEY` — то же через OrcaRouter, необязательно;
- `DEEPSEEK_API_KEY` — нужен старым скриптам сокращения субтитров (формат показан в `.env.example`);
- токен Hugging Face хранится после `hf auth login`, а не в `.env`.

Личные настройки лежат в `stt_config.local.json` рядом с `stt_config.json`. Его нет в git, и
`stt.run` с интерфейсом накладывают его поверх общего файла. Обычно там меняют языковую модель
или папки:

```json
{"paths": {"work": "/path/to/work", "finished": "/path/to/videos"},
 "llm": {"model": "openai/gpt-6.1-sol", "opencode": ["openai/*"], "router": ["orcarouter", "openrouter"]}}
```

Модели, подходящие под шаблон из `llm.opencode`, идут через OpenCode, в который вы вошли по
подписке ChatGPT (`opencode auth login`); если это не удалось, подхватывает платный роутер
(`"fallback": false` — остановиться вместо этого). Вкладка настроек в интерфейсе записывает в
этот файл только ваши отличия от общего. Ключи и токены больше никуда не вставляйте.

## 5. Быстрый старт

### Через браузер

```bash
bash scripts/run_ui.sh        # откроет http://127.0.0.1:7861 (PORT=... — другой порт)
```

Вверху страницы выберите сезон («＋ Новый сезон»: папка с оригинальными сериями; рядом предлагается папка
результатов `STT_<сезон>`, в ней лежит всё). На вкладке «Обработка» отметьте серии, выберите набор настроек и
нажмите «Начать». Браузер можно закрыть: работа продолжится. Если остановить, следующий запуск
продолжит с того же места. Рядом с полями папок кнопка «📁 Выбрать…» открывает окно выбора папки рабочего стола
(`zenity`), если страница запущена на компьютере с рабочим столом; иначе на странице открывается небольшой
обзор папок. Вверху каждой вкладки одна строка говорит, что вкладка куда записывает.

### Через командную строку

```bash
# одна серия целиком: озвучка тремя движками, проверки, сведение
subs_env/bin/python -m stt.run /path/to/season/ep01.mkv

# весь сезон по маске (маску возьмите в кавычки, чтобы её не раскрыла оболочка)
subs_env/bin/python -m stt.run "/path/to/season/*.mkv"

# остановиться после русского сценария озвучки, без синтеза голоса
subs_env/bin/python -m stt.run "/path/to/season/*.mkv" --until dub
```

Полезные параметры (все: `subs_env/bin/python -m stt.run --help`):

| Параметр | Что означает |
|---|---|
| `--preset NAME` | набор настроек, см. [раздел 6](#6-наборы-настроек) |
| `--engine f5,teratts,vosk` | какие голосовые движки использовать (по умолчанию все три) |
| `--until STAGE` | последний этап: `transcribe`, `glossary`, `speakers`, `translate`, `dub`, `stress`, `voiceover`, `check`, `mix` |
| `--force STAGE` | пересчитать этот этап и все после него |
| `--mode fast\|accurate` | только Whisper (fast) или две расшифровки, сведённые языковой моделью (accurate, по умолчанию) |
| `--start SEC --duration SEC` | обработать только кусок серии (для проверок) |
| `--no-subtitles` | не искать готовые субтитры |
| `--no-season-voices` | пропустить этап голосов сезона |
| `--out-root DIR` | куда класть рабочие папки серий (по умолчанию `paths.work`, то есть `output/stt`) |
| `--config FILE` | другой базовый конфиг |

Готовые этапы пропускаются, поэтому повторный запуск той же команды ничего не стоит и не
повторяет запросы к языковым моделям. Остановить работу можно в любой момент (Ctrl+C или
«Остановить» в интерфейсе) и запустить снова той же командой: готовые этапы пропустятся,
распознавание сохранит уже сделанные части, а озвучка — все уже озвученные реплики.

Один измеренный пример: серия около 86 минут на RTX 4070 Ti SUPER заняла около 50 минут на три
озвучки и сведение, когда расшифровка и перевод уже были; S20E01 целиком — 1 ч 15 мин. На другом
железе и других сериях цифры будут другими.

## 6. Наборы настроек

Набор настроек — это именованный список параметров, накладываемый поверх конфига. Порядок, побеждает
последнее: базовый `stt_config.json` < `stt_config.local.json` < набор < форма в интерфейсе или
параметры командной строки. Наборы действуют только на `stt.run`, на классический пайплайн — нет.

| Набор | Что делает |
|---|---|
| `main` (по умолчанию) | лучшее качество: голоса сезона, готовые субтитры, три озвучки, проверки ударений и речи |
| `upload` | `main` плюс сжатие видео примерно до 2 ГБ на серию |
| `fast` | только Whisper, только Vosk, без проверок ударений и речи, без голосов сезона и без поиска субтитров в интернете |
| `previous` | без голосов сезона, без субтитров, прежняя громкость |

В командной строке: `--preset upload`; в интерфейсе: переключатель «Набор настроек» на вкладке
«Обработка».

## 7. Как устроен пайплайн, по этапам

Этапы (имена для `--until` и `--force`): `transcribe`, `glossary`, `speakers`, `translate`,
`dub`, `stress`, `voiceover`, `check`, `mix`. У каждой серии своя рабочая папка, а серии одной
папки делят общий словарь сезона и банк голосов.

1. **transcribe** (на компьютере). Звук режется на куски с речью и распознаётся Whisper-ом
   (`--mode fast`) либо Cohere Transcribe вместе с Whisper-ом, чьи два текста языковая модель
   сводит в один (`--mode accurate`). Времена слов дают принудительным выравниванием (когда
   известный текст «накладывают» на звук). Видео также просматривается дважды в секунду в поиске
   вшитых титров и карточек с именами (OCR); текст титра берётся вместо распознанного, а русский перевод титров, карточек с именами и
   названий мест показывается прямо поверх английской надписи (дорожка субтитров, включена по
   умолчанию, в плеере её можно выключить). По умолчанию строки с титрами не озвучиваются (остаётся оригинальный звук;
   настройка `on_screen.voice`: `text` | `neutral` | `hero`), потому что кто их говорит — часто неясно. Здесь же определяются говорящие (раздел 8), а перед этим
   ищутся готовые субтитры (раздел 9).
2. **glossary**. Языковая модель составляет список имён, мест и терминов сезона с русским
   написанием. Раз в сезон она также получает состав (участников, прозвища, родство) из статьи
   сезона в Википедии или из интернета.
3. **speakers**. Языковая модель называет говорящих и ставит русскую подпись и пол, опираясь на
   словарь, состав сезона, карточки с именами на экране, банк голосов сезона и подсказки из
   субтитров. Здесь же работает этап голосов сезона (раздел 10).
4. **translate**. Перевод с английского на русский по репликам, каждая подгоняется под время,
   которое говорящий занимал. Слишком длинные реплики сокращаются; реплики с неверным родом
   («я сказал» / «я сказала») исправляются.
5. **dub**. Сценарий озвучки: какие реплики озвучивать и каким голосом. Короткие «ага» и «вау»
   поверх чужой речи остаются в оригинале.
6. **stress**. Ударения. Их ставит RUAccent; правило снимает ударение с коротких слов вроде «на»
   и «не» (кроме настоящих случаев, как «не было»); слова, оставшиеся без ударения, получают
   словарное; имена и спорные слова перепроверяют языковые модели (трое голосуют). Имя получает
   одно ударение на весь сезон. Затем одна сильная модель (gpt-6.1-sol) читает все реплики и
   отмечает заведомо неверные ударения, в том числе в словах, которые RUAccent взял из словаря
   («Само+а» вместо «Сам+оа»); по каждой отметке голосуют те же модели (на весь сезон слово
   исправляется, только когда согласны все три), и исправленное слово звучит одинаково во всём
   сезоне. Голосование не безошибочно: на одной серии оно дало 9 верных исправлений и 1 неверное. Отключается через `"stress_proofread": false`.
7. **voiceover** (на компьютере). Каждая реплика синтезируется выбранными движками и ставится на
   временную шкалу (раздел 11). Алгоритм сдвигает и ускоряет реплики, чтобы они не наезжали
   друг на друга, и просит сократить текст только при необходимости.
8. **check** (на компьютере). Каждый озвученный отрывок заново распознаётся по-русски
   (GigaAM-v3) и сравнивается с текстом; в `speech_check.md` перечислены неверно прочитанные или
   «проглоченные» слова. `review.json` и `review.srt` — список реплик, где голос мог быть не тот,
   для просмотра человеком. Туда же попадает каждая реплика, у которой род изменён по её голосу
   (около 3% реплик; на S51 из 26 изменённых 22 исправлены и 4 испорчены, верный род 86,2% -> 88,2%),
   с готовой правкой, которая это отменяет.
9. **mix** (на компьютере). Русская дорожка накладывается на оригинал (оригинал приглушается
   под голосом, раздел 12), кодируется в AAC и кладётся в один `.mkv` вместе с оригинальным
   звуком и русскими субтитрами. Каждый запуск движка добавляет свою звуковую дорожку.

## 8. Как определяются говорящие

В реалити-шоу много голосов, фоновых разговоров, криков и музыки, поэтому «кто произносит эту
реплику» — самое слабое место пайплайна. Цепочка такая:

1. DiariZen v2 делит звук на отрезки по говорящим (если нет `diarizen_env`, это делает
   pyannote). Он же даёт «эксклюзивный» слой: один говорящий в каждый момент, самый сильный из
   говорящих одновременно.
2. Каждый отрезок сравнивается с голосовыми отпечатками других говорящих моделью ResNet293
   (`speaker_refine`); отрезок, который звучит заметно ближе к другому говорящему, переходит к
   нему.
3. Каждое слово получает короткий голосовой отпечаток, и проход Витерби (метод, который выбирает
   самую правдоподобную последовательность говорящих) расставляет слова заново: он предпочитает
   того же говорящего, что и у предыдущего слова, если только голос явно не сменился
   (`word_speakers`, `stt/boundaries.py`).
4. Готовые субтитры с именами говорящих или метками смены голоса `>>` помогают (раздел 9).
5. Этап голосов сезона заново распределяет слова между людьми, названными во всём сезоне
   (раздел 10).
6. Языковая модель называет говорящих; ей помогают банк голосов сезона, состав сезона и
   карточки с именами на экране. Для говорящих с неизвестным полом пол определяется по
   каждой реплике отдельно, по голосу. У говорящих с известным полом род реплики меняется, только
   если обе модели (audeering и классификатор по отпечатку голоса) уверены в другом (меняется род,
   не герой; ведущий пропускается).

Насколько это работает, честно: на пяти сериях S51 E01-E05, где реплики размечены субтитрами для
слабослышащих, такая цепочка (без голосов сезона) ставит около 63,5% размеченных реплик на их
человека. По меткам смены голоса `>>` в S20 (четыре серии) F1 (мера, сочетающая полноту и
точность) определения смены говорящего выросла с 0,841 до 0,878 благодаря эксклюзивному слою и
пословному проходу. С голосами сезона цифры приведены в разделе 10. Похожие по голосу
люди и те, кто только кричит, по-прежнему иногда сливаются в одного. Проверяйте реплики, которые
отмечает программа (раздел 16).

## 9. Готовые субтитры

У многих серий уже есть английские субтитры с информацией о говорящих: файлы для слабослышащих
подписывают говорящего («SANDRA: ...»), а эфирные титры отмечают смену голоса знаками `>>`.
`stt.subtitles` ищет их до распознавания, в таком порядке:

1. дорожки субтитров внутри видео (английские текстовые форматы; дорожка для слабослышащих
   первой);
2. файлы `.srt` / `.vtt` рядом с видео и в его папке `subs/`, с тем же кодом серии (`S05E02`,
   `10x05`) или именем файла (русские файлы и собственные файлы программы пропускаются);
3. локальный архив: `subtitles.archive` — папка с файлом `manifest.jsonl`;
4. интернет (`subtitles.online`, источники без ключей: дополнение OpenSubtitles для Stremio, затем
   Gestdown) по значению `subtitles.imdb`.

`subtitles.imdb` — это либо один идентификатор IMDb, либо словарь `{"часть пути к видео": id}`
(срабатывает первая часть, найденная в пути; `null` значит «не искать в интернете»). В общем
конфиге заданы Survivor и The Amazing Race; у Australian Survivor стоит `null`. Для другого шоу
добавьте свою строку в `stt_config.local.json`.

Что это меняет: каждая строка субтитров привязывается к реально услышанным словам. Строки с
именем закрепляют свои слова за этим человеком; метки `>>` делают смену говорящего в этом месте
«дешевле». Результат поиска, в том числе «ничего не найдено», кэшируется в `subs.source.json` в
папке серии. Измерено на S51 E01-E05 (половина именованных строк даётся как подсказка, вторая
половина проверяется): данные строки выросли с 64,9% до 84,2% на своём говорящем (S51E01), а
строки, которые не давались, почти не изменились (59,7% → 59,8%). Отключается параметром
`--no-subtitles`.

## 10. Голоса сезона

Кластер диаризатора нередко смешивает нескольких людей, а пословный проход сравнивает слово
только с кластерами своей серии. Этап голосов сезона (`stt.season_voices`, включён по умолчанию,
модель `resnet293-ft`) вместо этого строит голосовой отпечаток каждого человека по всему, что
пайплайн назвал во всём сезоне (человеку нужно 20 слов), а затем заново распределяет каждое
слово каждой серии между этими людьми и неназванными кластерами серии. Языковая модель при этом
не используется.

- Нужно, чтобы серии дошли до этапа `speakers`. С маской `stt.run` сначала доводит до него все
  указанные серии, а другие серии той же папки, у которых уже есть расшифровка, тоже добавляют
  свои голоса. Работает и с одной серией.
- Серия, у которой уже есть `subs.ru.json` (то есть переведённая), не трогается, поэтому
  повторный запуск не повторяет ни перевод, ни озвучку. `--force speakers` назначает говорящих
  заново.
- Файлы первого прохода сохраняются как `*.before_voices.json`; `season_voices.json` записывает,
  что сдвинулось.
- Кнопка «Уточнить, кто говорит» на вкладке «Голоса сезона» считает их заново для выбранного сезона и больше ничего
  не обрабатывает (`stt.run <видео> --season-voices-only`). Переведённые серии остаются как есть.
- Вручную: `subs_env/bin/python -m stt.season_voices /path/to/work/season [--episodes "*S51E0[23]*"] [--dry-run]`.

Измеренная польза, на настоящем пайплайне с обученной моделью (`docs/experiments.md`):

| Проверка | До | С голосами сезона |
|---|---|---|
| Реплики S51 на своём человеке (E01-E05, размеченные реплики) | 68,4% | 71,6% |
| S20, F1 смены говорящего (четыре серии) | 0,879 | 0,897 |
| S29, F1 смены говорящего (E01, E03, E07) | 0,860 | 0,871 |
| Названные слова S51: верно / не тот / без имени | 63,7 / 29,5 / 6,8% | 69,4 / 30,6 / 0% |

Это улучшение, а не лекарство: около 30% слов всё равно попадает не к тому человеку. Кроме того,
этап может отдать несколько слов человеку, которого в серии нет (чужое имя вместо нейтрального
голоса). Для построения голосов хватает одной серии: по одной, двум, трём и пяти сериям S51 доля
верных была 69,2, 70,0, 69,6 и 69,4%. Владелец послушал серии, озвученные таким образом, и
сделал это поведением по умолчанию.

## 11. Голосовые движки

`voiceover.engine` по умолчанию равен `f5,teratts,vosk`: все три по очереди, каждый добавляет
в видео свою звуковую дорожку.

| Движок (`--engine`) | Где работает | Голоса |
|---|---|---|
| `f5` ESpeech | видеокарта, в `f5_env` | каждый человек своим голосом, клонированным по образцу 5-9 с, вырезанному из серий (банк голосов). Людей без образца озвучивает TeraTTS |
| `teratts` TeraTTS | видеокарта | один женский и один мужской голос (смесь `ru_f1` и `ru_f2`, и `ru_m5`); у ведущего сезона отдельный голос (`host_voice`) |
| `vosk` | процессор | встроенные голоса Vosk (49 женских, 56 мужских); ведущего озвучивает TeraTTS |

Любой движок повторяет реплику с другими случайными зёрнами, если проверка речи слышит
пропавшее или искажённое слово, и оставляет лучший дубль. Каждая синтезированная реплика
хранится в кэше (`output/tts_cache/`), поэтому повторный запуск или переозвучка после правки
синтезирует только изменившиеся реплики. При `voiceover.parallel_cpu` (по умолчанию) Vosk работает
рядом с движками на видеокарте. Тестовый кусок S29E05 в 10 минут тремя движками занял 25,4 мин
подряд и 16,4 мин в две параллельные линии с ограничением потоков процессора.

Параллельная работа на видеокарте (`"gpu": {"parallel": "auto"}`, в интерфейсе «Параллельная работа на видеокарте»).
Три ускорения запускают задачи на видеокарте одновременно: чтение надписей на экране рядом с разметкой
говорящих и распознаванием, сведение звука одного движка (выделение голосов) рядом с озвучкой следующего и сжатие
видео рядом с озвучкой. Измерено на карте 16 ГБ. Режим `auto` (по умолчанию) сначала спрашивает у `nvidia-smi`,
сколько на карте видеопамяти, и совмещает задачи, только если карта вмещает самую тяжёлую из соседних задач, саму
задачу и запас 1,5 ГБ (`stt/gpu_budget.py`: около 10,4 ГБ для надписей, 9,8 ГБ для сведения, 8,4 ГБ для сжатия) и столько
же свободно прямо сейчас. Иначе задачи идут по очереди (надписи после выравнивания, сведение до следующего движка,
сжатие при сборке видео): медленнее, результат тот же. Неизвестная карта считается маленькой. `on` — всегда
параллельно, `off` — никогда. Если само выделение голосов не помещается в память, оно ждёт 30 с, пробует ещё раз и
затем выполняется на процессоре. Пик видеопамяти задач, для которых у нас не было цифр (ESpeech, выделение голосов,
сжатие, процесс каждого этапа), пишется в `logs/vram_peaks.json` серии и в `f5_timing.json`.

Банк голосов (`stt.voice_bank`, вкладка «Голоса сезона») хранит голосовой отпечаток и образцы
для каждого названного человека сезона.

## 12. Громкость

По умолчанию: озвучка поднята на 3 дБ; музыка и эффекты оригинала опускаются на 6 дБ под
голосом, оригинальные голоса — на 12 дБ; весь микс приводится к -16 LUFS (мера громкости) с
ограничителем пиков. Голоса от музыки отделяет Hybrid Demucs. Оригинальная дорожка в видео не
меняется. Настройки: `mix.voice_gain_db`, `mix.rest_duck_db`, `mix.duck_db`,
`mix.loudness_lufs`, `mix.duck` в `stt_config.json` (`"duck": "all"` приглушает весь оригинал).

Послушать другие уровни, ничего не меняя: вкладка «Звук и размер видео» или
`subs_env/bin/python -m stt.mix_preview <папка серии> <видео> --engine f5 --voice-gain-db 6 --out piece.wav`
(кусок в 45 с; без `--start` берётся место, где речь встречается с самым громким оригинальным
звуком). Применить новые уровни к готовой серии без повторной озвучки:
`subs_env/bin/python -m stt.run <видео> --engine f5,teratts,vosk --force mix`.

## 13. Сжатие видео

По умолчанию выключено. `mix.video` — это `{"compress": false, "target_gb": 2.0, "codec":
"hevc_nvenc", "original_audio_kbps": 160}`. Картинка перекодируется в том же разрешении с таким
битрейтом, чтобы готовый файл получился около `target_gb` (1 ГБ = 10^9 байт). Используется кодировщик
видеокарты (`hevc_nvenc`, `h264_nvenc`) через PyAV; если он не открылся, берётся `libx265` /
`libx264` на процессоре. Набор `upload` включает сжатие.

Один измеренный результат: S51E01 (86 мин) стала 2,07 ГБ вместо 7,07 ГБ за 15 минут на RTX 4070
Ti SUPER; SSIM (мера сходства, 1 — одинаково) на куске в 60 с составил 0,959, мелкие детали кожи
на крупных планах становятся мягче.

Для уже готового видео:

```bash
subs_env/bin/python -m stt.video_compress FILE [--target-gb 2] [--codec hevc_nvenc] [--out path]
subs_env/bin/python -m stt.video_compress FILE --sample-minute 10 --sample-seconds 60   # кусок, чтобы оценить качество
```

Исходный файл не меняется; результат — `<stem>.small.mkv` рядом с ним (пробный кусок —
`<stem>.sample.mkv`). Все дорожки звука и субтитров сохраняются.

## 14. Интерфейс в браузере

`bash scripts/run_ui.sh`, адрес http://127.0.0.1:7861. Вкладки:

- **Полоса сезона** (над вкладками) — выбор сезона и «＋ Новый сезон» (у обеих папок кнопка «📁 Выбрать…»: окно
  рабочего стола, если есть рабочий стол и `zenity`, иначе обзор папок на странице; папка результатов
  `STT_<имя папки с оригиналами>` предлагается сама и создаётся по «Сохранить сезон»); один сезон для всех вкладок,
  запоминается в файле состояния интерфейса `ui.local.json` (не в git; прежние версии хранили его в
  `stt_config.local.json` в `ui.seasons`, оттуда он один раз читается). Сезоны рядом с папками из конфига находятся
  при первом запуске. Если выбран сезон без своих настроек, а у прежнего они были и отличаются от общих, страница
  спрашивает, какие взять. Первая строка каждой вкладки говорит, что вкладка куда записывает.
- **Обработка** — выбор серий (с таблицей их состояния), набора настроек, движков и параметров; запуск и остановка;
  строка состояния словами (что идёт сейчас, на каком месте, сколько осталось), таблица хода
  (общие этапы и столбец на каждый движок), «Контрольные точки» (что сохранено и можно ли
  останавливать), понятный журнал «Ход работы» (сырой лог — в «Подробный лог») и готовые файлы.
  Последняя обработка запоминается в `output/ui_last_job.json`: после перезапуска страницы или
  компьютера она снова видна (ещё идёт — за ней можно следить и её можно остановить; процесса
  нет — «прервано»), а «▶ Продолжить» запускает ту же команду с тем же файлом настроек: готовые
  этапы, озвученные реплики и оплаченные ответы не повторяются. «Пробный отрывок» озвучивает
  несколько минут с выбранной минуты в папку `_проба`, чтобы быстро проверить настройки.
- **Голоса сезона** — люди сезона и образцы голосов, по которым ESpeech озвучивает героев (✅ найден сам,
  ✋ указан вручную, ❌ нет, с причиной). Образец можно послушать, найти другой автоматически или указать отрывок
  вручную: выберите серию, впишите отрывки вида `12:30-12:41`, нажмите «Вырезать и послушать» (кусок вырежется,
  очистится от музыки, текст распознается и его можно поправить) и сохраните как образец человека; автоматический
  поиск такой образец уже не заменит. После изменения образца появится строка «Переозвучить ESpeech (N серий)»:
  заново озвучатся только реплики этого человека. Здесь же «Пересобрать все образцы», «Уточнить, кто говорит»
  (заново посчитать голоса сезона) и проверка имён.
- **Строка состояния** (под выбором сезона, на каждой вкладке) — единственная долгая задача, которая идёт сейчас
  (обработка, образцы, переозвучка, сжатие, пересведение): время, последняя строка о ходе и кнопка «Остановить»;
  после конца «✅ Готово» или «❌ Не получилось» с причиной. Долгая задача одна за раз; вторая кнопка скажет, какая
  уже идёт. Каждая кнопка отвечает сразу: долгие действия запускают задачу, средние показывают «⏳ …» на кнопке и
  строку о том, что происходит, быстрые отвечают сообщением.
- **Проверка и правка реплик** — все русские реплики, фильтры по отмеченным программой, оригинал
  и озвучка реплики, правка, обмен с Subtitle Edit и переозвучка только изменённого.
- **Звук и размер видео** — послушать кусок в 45 с с выбранными уровнями рядом с текущим
  миксом, найти самое громкое место, сохранить настройки, пересвести серию без новой озвучки,
  настройки сжатия, сжать готовое видео, пробный кусок в 60 с.
- **Настройки** — движки, модели, голоса, проверки, сведение. Общие настройки: `stt_config.local.json`, если на
  вкладке не выбран другой файл (новый файл создаётся как копия; выбор хранится в `ui.local.json`), сохраняются как
  отличия от стандартных. Настройки сезона: `<результаты>/season_settings.json`, снимок всех значений вкладки,
  действует только для этого сезона; переключатель «Сохранять изменения в» выбирает, куда пишет «Сохранить», а
  «Убрать настройки сезона» удаляет файл. «Сбросить» кладёт стандартные значения в выбранный файл. Там же очистка
  кэша озвучки.
  Поля расположены так, чтобы все подписи читались. Голоса Vosk выбираются по имени (номер, имя,
  пол), а кнопка «▶ Послушать» у каждого голоса проигрывает фразу выбранным сейчас голосом (её
  делает отдельный процесс на процессоре; образцы лежат в `output/voice_previews/`; первый образец
  Vosk готовится около 45 с, TeraTTS около 12 с, повторно — сразу).
- **Справка** — справка по-русски (`ui/help.md`).

Одновременно идёт одна задача. Текст интерфейса русский.

## 15. Выходные файлы и папки

Папки (`paths` в конфиге; личные значения — в `stt_config.local.json`):

- `work`: по папке на серию (по умолчанию `output/stt/<серия>/`);
- `season`: словарь сезона, состав, банк голосов и образцы голосов (по умолчанию — `work`);
- `finished`: готовые видео в папке с именем как у папки сезона, по умолчанию `STT_<сезон>` (если
  не задано — в рабочей папке каждой серии).

Внутри папки серии: `subs.en.json`, `subs.ru.json` (и копии `.srt`), `dub.ru.<engine>.json`,
`stress.json`, `speakers.json`, `glossary.json`, `ocr.json`, `words.json`, `subs.source.json`,
`subtitle_hints.json`, `season_voices.json`, `voiceover.<engine>/` (`export/track.wav`,
`report.md`, `speech_check.md`), `review.json`, `review.srt`, `logs/`.

Готовое видео — `<имя>.ru.mkv`, в котором каждая сделанная озвучка идёт отдельной звуковой
дорожкой (порядок задаёт `mix.track_order`, первая дорожка — по умолчанию), затем оригинальный звук
и русские субтитры. С `"mix": {"tracks": "separate"}` вместо этого получится отдельный
`<имя>.ru.<engine>.mkv` на каждый движок. Промежуточный WAV со сведением (~0,5 ГБ) удаляется
после кодирования, если не задано `keep_wav: true`. `output/`, `models/` и личные настройки
в `.gitignore`; в git попадают только код, конфиги и документация.

## 16. Правка реплик

Программа иногда приписывает реплику не тому человеку, путает мужской и женский голос, неудачно
переводит или ставит не то ударение. Поправить это можно без озвучки всей серии заново:

- во вкладке «Проверка и правка реплик» интерфейса, или
- в Subtitle Edit: `subs_env/bin/python -m stt.subtitle_edit export <папка серии> [--review] [--srt]`
  записывает реплики в `<серия>/edit/` (ASS: говорящий в колонке «Actor», пол — стиль «Мужской» /
  «Женский», «Не озвучивать» пропускает реплику; либо SRT вида `[Имя] текст`); поправьте файл и
  выполните `... import <папка серии> <файл> [--dry-run]`: он покажет изменения и запишет их в
  `corrections.json`. Не меняйте время реплик и колонку «Effect» (в ней номер реплики).

`corrections.json` в папке серии устроен по номерам реплик:

```json
{"123": {"gender": "female"}, "130": {"speaker": "Julie McGee"}, "140": {"text": "Новый текст"}, "141": {"skip": true}}
```

Следующий `stt.run` серии заново делает сценарий озвучки, проверку ударений, озвучку (синтезируются
только изменённые реплики), проверки и сведение. Ударение, поставленное как `+` перед гласной
(`зам+ок`), важнее всего остального и в субтитры не попадает. Ещё один ручной файл —
`speakers.override.json` (затем `--force speakers`).

## 17. Настройки

- `stt_config.json` — общие настройки: режим, модели, диаризатор, `season_voices`, `subtitles`,
  языковые модели (`llm`), `voice_bank`, `cast`, `translate`, `dub`, `voiceover`, `mix`, `crowd`
  (экспериментальный слой выкриков толпы, выключен), `presets`, `paths`.
- `stt_config.local.json` — ваши отличия, не в git, накладываются сверху.
- `voiceover_config.json` — подробности синтеза голоса и подгонки по времени (на него указывает
  `voiceover.config`).

Порядок: `stt_config.json` < `stt_config.local.json` < набор < форма в интерфейсе или параметры
командной строки. В интерфейсе после файла общих настроек (по умолчанию `stt_config.local.json`) идут настройки
сезона (`<результаты>/season_settings.json`, если файл есть), затем набор и форма; `stt.run` из командной строки
читает только `stt_config.local.json`. Языковые модели: один переключатель `llm.model` (по умолчанию
`openai/gpt-6-luna`) задаёт модель всех шагов, а `llm.stages.<шаг>` меняет её для одного шага.
Цены по шагам, измеренные на одной серии в 64 минуты, приведены в `docs/stt_local.md`.

## 18. Старый «классический» пайплайн

До основного пайплайна был более простой, для готовых русских субтитров:
SRT → JSON (`utils.srt_to_json`) → RUNorm + RUAccent (`utils.text_normalizer`: нормализация
чисел и ударения) → Vosk TTS (`synthesize.synthesize_cli`) → сведение (`utils.audio_mixer`).
Он по-прежнему на месте, а `uv run -m voiceover.pipeline run <subs.json> --out <папка>` озвучивает
готовые русские субтитры движками основного пайплайна. Наборы настроек на него не действуют.
Подробнее: раздел 4 в `AGENTS.md` и `docs/pipeline.md`.

## 19. Обучение модели голосов

Веса `models/speaker/resnet293-ft/avg_model.pt` — это модель голосов ResNet293, дообученная на
речи из Survivor: окна в 1 секунду вокруг слова, вырезанные так же, как их режет пайплайн, с
разметкой по субтитрам, где названы говорящие, 334 человека из 20 сезонов. На S51E01-E05 ошибка
«тот же голос / другой голос» снизилась с 25,0% до 20,6%. Скрипты лежат в
`scripts/speaker_training/`, запускаются по порядку из корня репозитория:

1. `build_words.py` — времена слов Whisper по обучающим сериям;
2. `align_lines.py` — привязывает каждую строку субтитров к реально сказанным словам;
3. `build_dataset.py` — собирает обучающие отрывки в один файл;
4. `train.py` — само обучение.

Что каждый берёт и пишет, сказано в их docstring-ах; папка с данными — `output/subs_train`. Это
исследовательские скрипты, сохранённые, чтобы модель можно было воспроизвести, а не отполированный
инструмент, и им нужны серии с субтитрами, где названы говорящие. Результаты экспериментов
вокруг них — в `docs/experiments.md`.
