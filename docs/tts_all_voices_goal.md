# Цель изменений (all-voices синтез + SPS)

Данная серия изменений введена для ускорения оценки и сравнения голосов много-спикерной модели Vosk TTS и получения простой количественной метрики производительности синтеза.

## Основные задачи
- Унифицированный прогон всех спикеров: один запуск генерирует WAV для каждого `speaker_id`, что позволяет быстро услышать различия и подобрать подходящий голос.
- Метрика символы в секунду (SPS): через manifest и последующие вычисления можно оценить скорость генерации/прозвучивания текста (темп артикуляции) и сравнить голоса на одинаковом материале.
- Снижение вариативности входного текста: нейтральный дефолтный текст упрощает сравнение; при необходимости можно подставить кастомный файл.
- Повышение надёжности акцентирования: санитизация и разбиение на чанки уменьшают риск ошибок RUAccent и последовательный fallback.

## Добавленные компоненты
- `synthesize/synthesize_all_voices.py` — CLI для синтеза всеми голосами: принудительный CPU, опциональное акцентирование, лимит спикеров для быстрого smoke-теста.
- `utils/text_sanitize.py` — нормализация кавычек/тире, удаление управляющих символов и эмодзи, схлопывание пробелов, безопасное разбиение на чанки.

## Почему это нужно
- Быстрый бенч: раньше требовалось вручную вызывать синтез по каждому голосу или писать временные скрипты; теперь есть стандартный инструмент.
- Сопоставимость: единые правила подсчёта символов (без пробелов/переводов строк и ударений) формируют воспроизводимые цифры для темпа.
- Диагностика: если конкретный голос даёт аномальный темп или артефакты, легко локализовать по manifest + метрикам.
- Расширяемость: структура допускает добавление новых параметров (шум, масштабирование, per‑speaker overrides) без изменения текущего интерфейса.

## Ожидаемая польза
- Сокращение времени ручной проверки голосов.
- Быстрота первичной интеграции SPS в пайплайн оценки.
- Более чистый вход для RUAccent, уменьшающий неустойчивость ударений.

## Что не менялось
- Базовая логика `synthesize_text` и существующие CLI синтеза одиночных строк.
- Механизм микширования и последующей сборки таймлайна.

## Следующие логичные шаги
- Добавить `utils/audio_metrics.py` для автоматического подсчёта SPS сразу после прогона.
- Включить флаг `--compute-sps` в `synthesize_all_voices.py` для энд‑ту‑энд сценария.
- Поддержка имен спикеров из `speaker_id_map` в manifest.

Документ отражает цель изменений, а не план реализации.
